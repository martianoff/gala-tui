# A tour of the mega demo, driven entirely by scripted input — keys AND mouse.
# Columns/rows are 1-based, as a terminal reports them. Coordinates were read
# off recorded frames at 120x36; re-check them if the layout changes.
#
# The tour is a story, not an inventory. An operator notices a failed build,
# finds out what broke, checks whether it is a trend, picks the target, reads
# the fix, signs in, ships it, and watches it land. Every screen appears
# because that sequence needs it — which is also what makes the recording
# worth watching twice, once for the app and once for the widgets.
#
# Ten beats, ~4.5s each. Even pacing is deliberate: an early beat that runs
# long reads as the demo being stuck, and a viewer who has already decided the
# demo is slow will not reach the part that sells it. If you add to a beat,
# take the time out of the same beat rather than letting it grow.
#
# Order is constrained by the app, not by taste. A sidebar click navigates,
# and the sidebar is only rendered on the screens that include it: overview,
# charts, forms, data, review. Builds is reached through the command palette.
# And on the forms screen a letter is text, so `t`, `?` and `q` only do their
# global jobs once the tour has left it.
#
# Sidebar nav rows, at column 14:
#   6 Overview   7 Builds   8 Pipelines   9 Logs
#  10 Charts    11 Forms   12 Data       13 Review
